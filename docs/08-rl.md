# 08 — Self-play RL agent

Phase 4 of the ML plan: a self-play RL policy with no dependence on `FaanBot`. It follows
phases 1–3 of [06-ml.md](06-ml.md) and does not replace them — those phases keep going and
their outputs (labels, heads, eval harness) are inputs here. Ships as the T4 "Expert" tier
([04-bots §2/§7](04-bots.md)), under M6 ([05-roadmap](05-roadmap.md)).

## 1. Goal and constraints

| Requirement | Detail |
| --- | --- |
| Independent of `FaanBot` | not a teacher, reward baseline, feature source, or training opponent |
| `FaanBot` / `ORACLE` | held-out evaluation opponents only; `FaanBot` actions allowed only as the §5 contingency bootstrap |
| Objective | hand point delta — never shanten ([06-ml §4](06-ml.md)) |
| `mahjong_core` | stays pure, stdlib-only, the reference implementation; speed-ups ship with equivalence tests and no `ENGINE_VERSION` bump |
| Determinism | a trajectory is a function of `(checkpoint, ruleset, env_seed, policy_seed)`; every eval game exports a replayable `GameRecord`. GPU training itself is not bit-reproducible. |
| Serving | numpy forward, p99 ≤ 5 ms single-sample CPU incl. encoding; fits the existing worker-pool job model; torch stays in the `ml` stage, numpy joins base deps |
| Layout | all training code in `server/ml/`; configs in `server/ml/configs/rl_*.yaml` |

**Why RL is feasible after all:** the env (engine + mask + encode) costs roughly 1/15 of one
`FaanBot` decision. [06-ml §7](06-ml.md)'s "RL is out" assumed per-decision single-sample
inference; with inference batched across many envs, rollout is bounded by the learner, not the
engine.

## 2. Environment — `ml/env.py`

- **Episode = one hand**, γ = 1. HK has no placement bonus, so per-hand payment is the exact
  objective across a game.
- **Vector env:** worker processes each step K envs into shared-memory buffers; the learner runs
  one batched forward per step. `fork` context per the existing `_mp_context` rule.
- **Self-play over all 4 seats:** every seat's decision is a sample; trajectories are regrouped
  per seat for GAE. Claim-arrival order from a seeded RNG, as `bots/selfplay.py`.
- **Masking:** `legal_mask` only; illegal logits → −∞; entropy over the masked distribution.
  Steps with one legal action are auto-played.
- **Ruleset as input:** `encode_ruleset` already carries `min_faan`, so the curriculum (§5)
  changes the input distribution, not the network. Legal `min_faan` values are `{0, 1, 3, 5}`.
- **Redaction:** policy inputs are built by a fast encoder straight from `GameState`; a parity
  test pins it equal to `encode_seat_view(seat_view(...))` — this is the leak guard.

### Engine speed-ups (in `mahjong_core`, behaviour-neutral)

| Change | Effect |
| --- | --- |
| cache the winning-shape check on type counts (`hand_is_winning_shape` → `decompose` is ~60% of engine time) | ~2.4× engine, outcomes identical |
| table lookup for `tile_id_type` (enum construction is ~15%) | small |
| fast encoder writing into a preallocated buffer | removes the `SeatView` → dict → numpy hop |

Escalation only if the R0 measurement says the env is the bottleneck: compile `mahjong_core`
with mypyc (already `mypy --strict`, zero source divergence) → Rust port behind a differential
test against the Python reference.

## 3. Model — `ml/policy_net.py`

**Encoder v2** — seat-centred `encode_seat_view` layout plus: claimable-tile plane (needed for
relative chow ids), last-discard marker, per-seat discard recency, suji. **Oracle channels**
(critic, and the policy during curriculum only): opponents' concealed hands, wall composition,
next-k draws.

| Part | Shape |
| --- | --- |
| Policy trunk | `DangerNet`-style 1-D pre-activation ResNet + SE, 37-wide tile axis, ~96 channels × 6–8 blocks (sized by the 5 ms serving budget) |
| Policy head | tile-equivariant: 3 conv channels × 34 (discard / concealed kong / added kong) + 7-way global head → 109 |
| Oracle critic | separate trunk of the same shape, input = policy input + oracle channels; training-only, never served |

**Auxiliary heads** (exact labels, weights annealed but never zero):

| Head | Label | Source |
| --- | --- | --- |
| per-opponent tenpai / legal wait (34) / faan class | `bots/labels.py` | phase 1 |
| own P(win), E[points \| win], P(deal-in) | hand outcome | phase 2 |
| hidden tiles: opponents' concealed counts (3×34), wall composition | `GameState` | phase 2b |
| shanten / ukeire per discard | `mahjong_core.shanten` | early curriculum only |

The phase-1 `DangerNet` is the reference: the trunk's danger head should reach its AUC.

## 4. Algorithm — `ml/ppo.py`

- **PPO** with masking, per-seat GAE, PopArt value normalisation, 2 epochs per batch.
- **Asymmetric critic:** V(full state) as baseline from step 0 — unbiased, removes draw-luck
  variance.
- **Oracle dropout:** the policy sees oracle channels early, scaled by a Bernoulli keep mask
  annealed 1 → 0; no oracle-to-blind distillation (a blind student averages a teacher whose
  push/fold depends on hidden hands, [06-ml §6.4](06-ml.md)).
- **Reward:** own payment / 32 at hand end, zero-sum, unclipped (clipping biases toward cheap
  hands).
- **Shaping:** potential-based only, Φ = −β·shanten with Φ(terminal) = 0; β annealed to 0
  before `min_faan` reaches 3.
- **ACH** (regret-based PPO variant) as an R3 ablation.

## 5. Curriculum (cold start)

Random play wins ~1–2% of hands even at `min_faan = 0`, so lowering `min_faan` alone is not
enough; hand-building has to be learned first.

| Stage | Opponents | `min_faan` | Oracle to policy | Shaping β | Advance when |
| --- | --- | --- | --- | --- | --- |
| C0 | frozen tsumogiri bots (never claim or win) | 0 | hands + next 13 draws | 1.0 | win rate ≥ 40% |
| C0b | same | 0 | draws k: 13 → 0 | 1.0 → 0.5 | blind win rate ≥ 25% |
| C1 | self-play | 0 → 1 → 3 | keep prob → 0 | 0.5 → 0 | at `min_faan` 3, oracle 0, β 0: win ≥ 18%, sub-min tenpai ≤ 0.32 |
| C2 | league (§6) | 3, 20% other presets | 0 | 0 | R3 gates |

**Contingency:** if C1 is below 10% win rate after 1B decisions, warm-start by cloning
`FaanBot` actions with a KL anchor decayed to 0 within 0.5B decisions; the final agent must
beat the anchor-zero checkpoint (paired CI > 0).

Optional bootstrap that stays within the independence rule: pretrain the trunk's auxiliary
heads on the phase-1 v3 dataset (states and exact labels only, no actions).

## 6. League — `ml/league.py`

| Share | Opponents |
| --- | --- |
| 50% | current policy in all seats |
| 35% | past snapshots (every ~50M decisions, ≤ 32 kept), sampled by win rate against them |
| 15% | reward-perturbed persona snapshots: aggressive (own win ×1.3), defensive (deal-in ×1.5) |

Heuristic bots never enter the pool, so evaluation against them stays held out. Track the
exhaustive-draw rate as the passivity/collusion canary.

## 7. Evaluation

- **Gate:** paired-duplicate CI ([04-bots §8](04-bots.md)), candidate × 1 vs `FaanBot` × 3,
  on fresh seeds (tune and gate on different seed sets), plus a bootstrap CI. Also vs `ORACLE`
  (gap to ceiling, not a target) and mixed tables (`EfficiencyBot`, `FaanBot` personas).
- **Metrics:** points/game, win, deal-in, avg winning faan, tenpai-at-draw,
  `tenpai_rate_on_sub_minimum_hand`, exhaustive-draw rate, exploiter gain, agreement with
  `FaanBot` (reported, not gated).
- **Sample size:** SD per duplicate set is ~16–19 points/game (from the existing arena CIs).
  For 80% power: δ = 5 → ~110 sets, δ = 2 → ~700, δ = 1 → ~2,800.
- **During training:** learned-only duplicate matches against league snapshots (Elo); `FaanBot`
  gates only at milestones.

## 8. Data

On-policy, transient. Kept: checkpoints (league ≤ 32 + gate winners), every eval `GameRecord`,
`metrics.jsonl`, and a 1% raw-count trajectory sample (rolling cap) for debugging. Run metadata
pins `ENGINE_VERSION`; the env refuses to start on a mismatch.

Budget, in decisions (1B ≈ 11M hands; estimates, ±3×): C0–C1 0.3–1B, beating `FaanBot` 2–5B.

## 9. Milestones

Phases 1–3 continue per [06-ml §5](06-ml.md). R0–R1 depend only on the engine and phase-1
labels and can run alongside phases 2–3; R2 onward starts once phase 1's offline gate is met.

| # | Deliverable | Exit criteria |
| --- | --- | --- |
| R0 env | engine speed-ups + equivalence tests; `ml/env.py`; fast encoder; `GameRecord` export | end-to-end rollout with batched inference measured and recorded here; encoder parity test; same seed → same trajectory; env games replay via `reduce` |
| R1 model | encoder v2; `PolicyNet` + oracle critic + auxiliary heads; numpy export with parity test | p99 ≤ 5 ms incl. encode (slow-marked test); danger head within 0.02 AUC of `DangerNet`; hidden-tile head beats uniform-over-unseen |
| R2 cold start | `ml/ppo.py`, `ml/curriculum.py`, `configs/rl_*.yaml` | C1 exit (§5); paired CI > 0 vs `EfficiencyBot` |
| R3 league | `ml/league.py`, personas, ACH ablation | paired CI > 0 vs `FaanBot` on ≥ 1,000 fresh sets; not worse on mixed tables; sub-min tenpai not worse. Stretch: ≥ +5 points/game |
| R4 ship | `bots/learned.py` `LearnedBot` in `BOT_REGISTRY`; numpy in base deps; weights artifact; "Expert" difficulty | [06-ml §6.5](06-ml.md) gate vs the best of phases 1–3; p99 ≤ 5 ms on the server CPU; bot load not regressed |

## 10. Risks

| Risk | Handling |
| --- | --- |
| env slower than the learner end-to-end | R0 measurement; mypyc → Rust ladder (§2) |
| curriculum stalls | oracle draws, annealed shaping, auxiliary pretraining; §5 contingency |
| heavy-tailed payouts destabilise the value | PopArt, oracle critic, larger batches |
| passive/collusive self-play equilibrium | draw-rate canary, league diversity, held-out heuristic eval |
| shaping residue (speed bias) | β = 0 well before any gate; sub-min tenpai canary |
| hidden info leaking into the policy | encoder parity test; oracle channels at keep prob 0 before any gate |
| `ENGINE_VERSION` bump mid-run | pinned in run metadata |
